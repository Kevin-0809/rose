# 报表明细导出阶段组件设计

## 目标

将报表明细导出的交易级明细、字段级明细和汇总报表生成逻辑拆分到独立组件，并由 `ReportExportBatchRunner` 按固定顺序统一调度：交易级明细、字段级明细、汇总报表。

任务详情页展示纵向三阶段进度：已完成阶段为绿色，执行中阶段为蓝色，待执行阶段为灰色；失败时当前失败阶段为红色，后续阶段为未执行。

## 架构

新增不可变 `ReportExportContext`，包含 `batchId`、`reportDate`、`exportTime`、交易目录和字段映射。新增三个步骤组件，均提供 `run(ReportExportContext)`：

- `TransactionDetailExportStep`：按服务码并行游标读取交易与响应码，生成交易级问题明细。
- `FieldDetailExportStep`：读取字段比较数据，按既有归一化和映射规则生成字段级问题明细。
- `SummaryExportStep`：读取交易和字段比较数据，按领域生成汇总行。

`ReportExportBatchRunner` 只加载共享配置、构造上下文并依次调用上述组件，不保留任一领域数据生成逻辑。

## 阶段状态与失败处理

`ana_report_export_command.current_stage` 使用稳定枚举值：`TRANSACTION_DETAILS`、`FIELD_DETAILS`、`SUMMARY`，空值代表尚未进入阶段或任务已成功完成。

每个步骤启动前，调度器通过命令服务写入当前阶段。步骤成功后继续下一个步骤；任一步骤抛出运行时异常时，调度器立即停止，异步执行器将命令置为 `FAILED`，且保留 `current_stage` 以定位失败位置。任务成功时清空 `current_stage` 并置为 `SUCCEEDED`。

本次重构保持现有数据生成、幂等写入和事务范围，不改变源表读取范围、表结构之外的数据模型或下载接口。

## 页面

详情页的任务状态区域添加纵向阶段列表：

- 已完成阶段显示绿色勾选图标和“已完成”。
- 当前 `RUNNING` 阶段显示蓝色编号图标和“处理中”。
- 尚未开始阶段显示灰色编号图标和“等待”。
- `FAILED` 批次的 `current_stage` 显示红色失败图标和“失败”；其后的阶段显示“未执行”。
- `PENDING` 状态下三阶段均为等待。

页面既有三秒轮询继续调用进度接口，接口返回的 `currentStage` 将驱动任务详情页状态更新；列表页保持现有紧凑进度条。

## 测试

- `ReportExportBatchRunner` 测试验证固定调度顺序，以及某步骤失败时后续步骤不执行。
- 命令服务测试验证当前阶段写入、成功清空和失败保留。
- 控制器及模板测试验证详情模型携带阶段状态和纵向阶段列表渲染。
- 三个步骤组件的现有数据生成测试迁移到各自组件，确保统计、字段归一化和交易明细规则保持不变。
