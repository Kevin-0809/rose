# 字段级差异问题跟踪文本导出设计

## 目标

在字段级差异页面增加独立的“导出问题跟踪表”操作。用户选择源批次后，系统从 `ana_field_diff_result` 查询字段级差异，按 SQL 规定归一为问题跟踪行，生成 UTF-8 文本文件，并将每条导出行 1:1 写入字段级导出流水表。

## 页面与接口

- 在 `/samples/field-diffs` 页面增加“导出问题跟踪表”按钮。
- 按钮仅提交 `batchId` 到 `GET /samples/field-diffs/tracking-export`。
- 未填写批次时前端阻止提交并提示“请选择批次后导出”；接口也校验该条件。
- 下载文件名为 `fielddiff_hf_{yyyyMMddHHmmss}.txt`，响应为 UTF-8 `text/plain`。

## 数据口径

- 源表仅为 `ana_field_diff_result`，查询条件仅为 `batch_id = :batchId`。
- 按 `service_code + soap_field_name` 分组，并通过 `row_number() over (... order by random())` 为每组随机选择一条样例记录。
- 对每个服务码，用 `ana_tran_catalog` 中 `catalog_id` 最小的一条记录补充交易名称、交易负责人和组别；交易码保留选中的字段差异记录的 `tran_code`。
- 字段名为非空的 SOP、SOAP、BizJSON、字段中文名，以逗号拼接。
- 问题描述为 `528字段值：{orig}；CCBS字段值：{dest}；字段映射状态：{status}`。
- 业务日期和登记日期均为导出服务器当前自然日期，格式 `yyyyMMdd`；问题级别固定为“字段级”。
- 问题类型、初步问题分析、最终处理方案、解决日期、需协调、解决人员、缺陷修复日期初始为空。

## 文本格式

输出 UTF-8 文本，使用 `!^` 分隔、LF 换行，列顺序为：

1. 业务日期
2. 组别
3. 序号
4. 批次
5. 交易码
6. 交易名称
7. 问题级别
8. 登记日期
9. 字段名
10. 问题描述
11. 交易负责人
12. 问题类型
13. 初步问题分析
14. 最终处理方案
15. 解决日期
16. 需协调
17. 解决人员
18. 流水号
19. 缺陷修复日期

所有输出值在写出前将 CR、LF 和 `!^` 替换为空格，防止下游解析发生行列错位。

## 导出流水

新增 `ana_field_diff_tracking_export`，保存导出时间、源批次、业务日期、行号、服务码、交易码、交易名称、组别、字段路径、映射状态、528/CCBS 字段值、负责人、样例流水号、问题级别、登记日期、字段名、问题描述及全部整改预留字段。每一文本数据行恰对应一条流水记录。

为 `(source_batch_id, service_code, soap_field_name)` 和 `export_timestamp` 创建索引。另提供可重复执行的 GaussDB 手工建表脚本，避免部署库缺表。

## 事务与测试

- 在单个事务中流式读取结果、写入流水并写临时文本文件；提交后才将文件传输给响应，最后删除临时文件。
- JDBC 查询使用前向只读语句和正数 `fetchSize`，避免大批次全量加载内存。
- 测试以提供的 SQL 为验收依据，覆盖随机每组一条、目录首条补充、19 列、字段名拼接、问题描述、落库一致性、回滚无输出、提交后输出、特殊字符清理和下载响应。
