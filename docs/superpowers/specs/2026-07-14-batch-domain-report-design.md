# 批次领域报表设计

## 目标

在“执行分析”下新增“批次领域报表”独立菜单与页面。用户手动触发当前批次的异步汇总任务，查看按领域聚合的交易结果、字段统计和配置缺口。

## 菜单与页面

新增路由 `/sampling/domain-reports`，使用 `batch-domain-reports` 作为导航活动标识。页面包含当前可生成批次的选择框、生成按钮、任务状态、报表主表和配置缺口提示区。

当前可生成批次指原始 `msg_flow_log_response`、交易比对和字段差异明细仍未被下一批清理的批次。历史批次仅可读取已持久化报表，不能重新生成；重跑请求必须返回“源明细已清理”的明确提示。

## 汇总口径

`msg_flow_log_response` 保持原样，不新增或更新拆分字段。汇总任务只读该表，临时使用 `split_part(txn_code, '&', 1)` 取得服务码，以 `service_code` 关联交易目录的 `module_name`。

主表按批次和领域聚合：

| 列 | 口径 |
| --- | --- |
| 覆盖 528 接口数 | 当前领域去重后的响应日志服务码数。 |
| 发送交易量 | 当前领域响应日志记录数。 |
| 528 成功 / CCBS 失败 | `comp_result = '2'` 数量。 |
| 528 失败 / CCBS 成功 | `comp_result = '1'` 数量。 |
| 二者均失败，响应码一致 | `comp_result = '3'` 数量，正常结果。 |
| 二者均失败，响应码不一致 | `comp_result = '8'` 数量，关注结果。 |
| 二者均成功 | `comp_result = '4'` 数量。 |
| 字段总数 | 当前领域覆盖服务的字段映射配置，按 `(tran_code, service_code, std_field_name)` 去重。 |
| 差异字段 | 当前批次已映射差异字段，按相同唯一键去重。 |
| 无差异字段 | 字段总数减差异字段。 |

## 持久化与性能

汇总任务先对响应日志、交易比对、字段映射和字段差异分别按服务码聚合，再关联领域，避免对 5,000 万响应记录和上亿比对明细进行放大连接。结果写入批次领域交易统计表、批次领域字段统计表和批次配置缺口表；页面只读取这些小表。

批次配置缺口表保存两类项目：无法由服务码关联交易目录的响应服务，以及 `mapping_status = 'UNMAPPED'` 的字段差异。它们不纳入主表领域统计。

## 任务状态与一致性

生成任务具有 `PENDING`、`RUNNING`、`SUCCEEDED`、`FAILED` 状态。任务完成前不发布新报表；成功后以一次性替换该批次的三类汇总数据方式发布，避免页面读取半成品。

## 验证

测试覆盖菜单入口、页面模板、各统计聚合口径、源明细缺失时的重跑拒绝、配置缺口归类和任务状态。浏览器验证生成、轮询状态、报表展示及窄屏横向表格滚动。
