# 全量回放交易清单与交易量检查设计

## 目标

在“数据准备”下增加两个相互关联但职责独立的功能：

1. 维护全量回放交易清单，支持页面增删改查、精简查询、分页和 11 列 Excel 全量导入。
2. 手工检查回放交易量，识别无交易量的清单交易、识别当前清单之外的交易流水，在用户确认后清理主库流水并启动既有交易码迁移任务。

两个功能均服务于当前全量回放准备流程。清单是检查的输入快照；检查批次保存历史结果，便于审计和重复核对。

## 已确认规则

- 完整 528 交易码由图片 Excel 的 A 列和 B 列拼接而成：B 有值时为 `A-B`，B 为空时为 `A`。数据库不单独保存 B 列。
- 完整 528 交易码是业务主键，不使用自增 ID；新增时必填，编辑时只读，更换交易码需删除后新增。
- 除完整 528 交易码外，其余清单业务字段均为可空 `varchar(200)`。
- “是否需要参与回放”只允许“是”“否”或空值。
- “业务领域（沙箱）”为自由文本。
- “批次”只保存 `查询`、`动账` 或空值；Excel 中按原值前两个字符归类。
- “最近交易日期”按字符串保存；非空时必须是合法的 8 位 `yyyyMMdd`。
- Excel 导入保持图片中的 11 列格式，表头顺序固定；A、B 列在解析阶段拼接。
- Excel 导入采用全量替换：整份文件解析、校验成功后，在同一事务中清空旧清单并写入新清单。空数据文件、重复交易码或任意行校验失败时整批失败并保留旧清单，错误信息包含行号。
- 每次导入都生成当前清单快照语义；检查确认执行时若清单已发生变化，应阻止执行并要求重新检查。
- 检查结果按完整 528 交易码汇总，不按报文类型拆分交易量。
- 交易量定义为 request 和 response 按 `(source_ip, trans_id)` 成对存在的完整流水数；`txn_code` 格式为 `service_code&报文类型`，报文类型为 `bzjson`、`sop`、`soap`。
- 检查映射时先查 `tp_online_service_in`：去掉 `txn_code` 的报文类型后，用 `replace(esf_service_code, '.', '')` 匹配基础服务码，取得 `tran_code`。查不到时再按 `ana_tran_code_service_mapping."528_service_code"` 查找 `tran_code`。
- 一个服务码映射多个 528 交易码时，只要任意一个交易码仍在当前回放清单中，就保留该服务码流水。
- 两张映射表都查不到的服务码列入待清理。
- 清理只作用于 `primary`，不修改 `bxds`；清理全部历史数据，并按完整流水成对删除 request 和 response。
- 无交易量交易码确认执行后调用现有交易码迁移任务：最近 30 个自然日、每种报文类型最多迁移 N 条，N 默认 100 且可配置。现有迁移任务的映射优先级和其他行为保持不变。
- 检查与清理/迁移分两步：开始检查只读并落库；确认执行后才清理和启动迁移。

## 页面设计

### 全量回放交易清单

导航入口：`数据准备 -> 全量回放交易清单`。

列表页包含：

- 顶部 `导入 Excel`、`新增交易`。
- 查询条件：完整 528 交易码、528 交易名称、业务领域、批次、是否参与回放。
- 分页列表，展示 10 个业务字段、创建时间、更新时间和操作。
- 行操作：编辑、删除。

新增/编辑使用独立表单页。完整 528 交易码新增时可编辑，编辑时只读；其余字段按已确认的文本、下拉和日期格式校验。

Excel 导入失败时展示错误行、错误原因和原清单保留提示；成功时展示写入条数和导入时间。

### 回放交易量检查

导航入口：`数据准备 -> 回放交易量检查`。

页面包含：

- `开始检查` 按钮。
- 迁移数量 N 输入项，默认 100，可配置。
- 固定检查范围提示“最近 30 个自然日”。
- 当前批次摘要：清单交易码数、有交易量数、无交易量数、待清理服务码数、待清理流水数、批次状态。
- 当前批次结果，分别分页展示：无交易量交易、待清理服务码/流水、未找到映射流水。
- `确认执行` 按钮，仅在批次处于 `WAITING_CONFIRM` 且清单未变化时可用。
- 历史批次分页列表，展示批次号、创建时间、N 值、无交易量数、清理数、迁移任务状态，并可进入批次详情。

建议状态：`CHECKING`、`WAITING_CONFIRM`、`EXECUTING`、`COMPLETED`、`FAILED`。

## 数据模型

### `ana_replay_transaction_catalog`

使用完整 528 交易码作为主键，保存：

- `tran_code` varchar(200) primary key
- `tran_name` varchar(200)
- `business_domain` varchar(200)
- `batch_type` varchar(200)
- `new_core_tran_code` varchar(200)
- `new_tran_name` varchar(200)
- `replay_required` varchar(200)
- `original_service_scene_code` varchar(200)
- `new_service_scene_code` varchar(200)
- `latest_transaction_date` varchar(200)
- `created_at`、`updated_at`

### `ana_replay_volume_check_batch`

保存一次手工检查和执行的生命周期：

- `check_id` 主键
- `status`
- `catalog_snapshot_time`
- `sample_size`，默认 100
- `lookback_days`，固定 30
- `catalog_count`
- `no_volume_count`
- `cleanup_service_count`
- `cleanup_row_count`
- `actual_cleanup_row_count`
- `migration_command_id`
- `created_time`、`started_time`、`ended_time`
- `error_message`

### `ana_replay_volume_check_detail`

每个清单交易码一条记录，保存交易名称、业务领域、批次、映射服务码数量、30 日完整交易量、检查状态、迁移状态和错误信息。状态至少包括 `HAS_VOLUME`、`NO_VOLUME`、`NO_MAPPING`、`MIGRATION_STARTED`、`MIGRATION_COMPLETED`、`MIGRATION_FAILED`。

### 清理明细

为支持展示“哪些交易数据被清理”，清理明细按基础服务码保存，记录映射出的 528 交易码集合、是否命中当前清单、待清理完整流水数、实际删除数和执行状态。清单外或两张映射表均未命中的服务码进入待清理集合；任一映射交易码命中清单的服务码不进入待清理集合。

## 执行流程

### 检查

1. 读取当前清单并固定快照时间。
2. 从 `primary` request/response 读取三种报文类型的基础服务码和流水键。
3. 按确认的映射顺序取得 528 交易码集合。
4. 以 `(source_ip, trans_id)` 配对后按 528 交易码合计完整流水量。
5. 识别无交易量清单交易、清单外服务码和未找到映射服务码。
6. 写入批次、交易码明细和清理明细，状态置为 `WAITING_CONFIRM`。

检查阶段不删除任何流水、不创建迁移命令。

### 确认执行

1. 校验批次状态和清单快照未变化；不满足时拒绝执行。
2. 进入 `EXECUTING`。
3. 在 `primary` 中按 `(source_ip, trans_id)` 删除待清理服务码的 response，再删除 request；记录实际删除数。
4. 对无交易量交易码调用现有交易码迁移命令，传入 N=批次配置值、lookback days=30，并保存 `migration_command_id`。
5. 迁移任务完成后汇总批次和明细状态；异常时标记 `FAILED` 并保留已完成清理和迁移信息。

清理与迁移命令创建应在清晰的事务边界内完成。既有迁移任务的异步执行、取消、续传和映射优先级不改变。

## 错误处理与并发

- 同一批次不能重复确认执行。
- 检查失败时不发生删除和迁移。
- 清单导入与检查确认并发时，通过清单快照时间检测变化并阻止旧批次执行。
- 清理或迁移部分失败时保留批次状态、已处理数量和错误信息，禁止静默重试造成重复删除或重复创建任务。
- 流水服务码两张表均未命中时按已确认规则待清理；无法确定服务码报文类型时只按合法三种类型处理。

## 测试范围

- 清单表 CRUD、主键只读、精简查询、分页。
- 11 列 Excel 表头、A+B 拼接、批次归类、日期校验、三态回放字段、全量替换和失败保留旧数据。
- `txn_code` 服务码/报文类型拆分及三种类型完整流水配对统计。
- `tp_online_service_in` 优先、`ana_tran_code_service_mapping` 回退、多个 528 交易码命中任一即保留、双表未命中待清理。
- 清单外服务码全部历史流水识别、request/response 成对删除和数量记录。
- 无交易量交易码迁移的 30 日范围、N 默认值及可配置值。
- 批次状态、清单变化阻断、重复确认、失败记录、历史批次分页和详情分页。
- 控制器、Thymeleaf 模板、导航入口和现有迁移功能回归测试。
