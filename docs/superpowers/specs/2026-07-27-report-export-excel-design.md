# 报表明细导出 Excel 设计

## 目标

在“报表明细导出”批次列表的操作列中，为已完成（`SUCCEEDED`）批次提供 Excel 下载。工作簿包含汇总信息，以及按领域划分的问题明细 Sheet。导出必须以流式方式处理大数据量，避免在应用内存中聚合明细数据。

## 入口与状态

- 新增下载接口：`GET /report-exports/{batchId}/excel`。
- 仅 `SUCCEEDED` 批次允许下载；不存在、未完成或失败批次不生成文件并返回对应 HTTP 错误。
- 列表中所有批次保留“查看结果”；仅 `SUCCEEDED` 批次额外显示“导出 Excel”。
- 文件名使用批次号，例如 `报表明细导出-RPT20260727.xlsx`，响应使用 `.xlsx` 的内容类型与附件下载头。

## 工作簿结构

### 汇总信息 Sheet

- 固定为第一个 Sheet，名称为“汇总信息”。
- 使用参考图的绿色双层表头：批次、领域、覆盖528接口、发送交易量；“发送统计”合并单元格，下设“528成功/CCBS失败”“528失败/CCBS成功”“二者均失败”“二者均成功”；成功率、差异字段数。
- 数据来自 `ana_report_export_summary`，按领域排序。

### 领域 Sheet

- `ana_tran_diff_tracking_export` 和 `ana_field_diff_tracking_export` 的记录按 `module_name` 分到同一领域 Sheet。
- 每个领域 Sheet 使用一张统一的问题明细表，交易级与字段级记录混排。表头为蓝色，启用自动筛选、冻结首行、边框和自动换行；字段名称与参考图保持一致：领域、序号、批次、交易码、交易名称、问题级别、登记日、字段名、问题描述、交易负责人、问题类型、初步问题分析、最终处理方案、解决日期、需协同组、解决人员、流水号、缺陷修复日。
- 跟踪表中已有值的列直接导出，包括交易负责人、流水号、问题类型、初步问题分析、最终处理方案、解决日期、需协同组、解决人员、缺陷修复日；没有值的人工问题跟踪列保持为空。
- 避免 Excel Sheet 名非法字符与长度限制；重复或截断后的领域名称追加稳定序号以确保唯一。

## 行映射

### 交易级

- `问题级别` 固定为“交易级”。
- `字段名` 由交易比较类别生成：
  - `comp_result = 1`：`528失败/CCBS成功`。
  - `comp_result = 2`：`528成功/CCBS失败`。
  - `comp_result = 3` 或 `comp_result = 8`：`528失败/CCBS失败`。
- `问题描述`：`528错误码：{orig_error_code}；描述：{orig_error_desc}；CCBS错误码：{dest_error_code}；CCBS错误描述：{dest_error_desc}`。缺失值输出为空文本，不以 `null` 字面量导出。

### 字段级

- `问题级别` 固定为“字段级”。
- `字段名` 按非空字段以 ` | ` 拼接：`soap_field_name`、`sop_field_name`、`bizjson_field_name`、`field_cn_name`。
- `问题描述` 仅根据实际值的空/非空状态脱敏：`528：有值/无值；CCBS：有值/无值`。不导出原始字段值。
- 跑批落库时，字段差异记录根据服务码、交易码和归一后的 SOAP 字段名查询 `ana_field_mapping`，写入 `sop_field_name`、`soap_field_name`、`bizjson_field_name`、`field_cn_name`；无匹配映射时保留已有 SOAP 字段名，其余字段为空。

## 流式实现

- 使用 Apache POI `SXSSFWorkbook`，设置有限行窗口；不使用普通 `XSSFWorkbook` 聚合完整明细。
- 汇总数据量很小，可常规查询。领域清单先通过轻量的去重查询取得。
- 对每个领域，交易级和字段级均从已完成批次对应的 `ana_tran_diff_tracking_export`、`ana_field_diff_tracking_export` 使用 JDBC 顺序读取，将每一行立即写入 `SXSSFSheet`；不构建全量 `List`，不回查会被下一次跑批清理的 `tss_*` 表。
- 查询层应配置适配 PostgreSQL 的流式读取语义（事务内游标、合理 `fetchSize`），并通过回调或 `ResultSetExtractor` 直接消费行。
- 工作簿直接写入 HTTP 输出流。无论成功、写入失败或客户端中断，都在 `finally` 中关闭工作簿、释放数据库资源并调用 `dispose()` 清除 SXSSF 临时文件。
- 同一 Sheet 先写交易级，再写字段级；序号在该领域内连续递增。

## 测试

- MVC 测试：已完成批次返回 `.xlsx` 下载，未完成批次被拒绝；列表仅为已完成批次显示下载链接。
- 工作簿测试：校验第一个 Sheet、按领域 Sheet、双层汇总表头、统一明细表头、过滤冻结配置及关键样式。
- 映射测试：校验三类交易比较类别、响应码不一致、交易描述拼接、字段名非空拼接、四种有值/无值组合及不泄露原始字段值。
- 流式写入测试：通过大量模拟明细验证顺序输出与临时资源释放，不要求将全量记录加载到测试中的集合。
