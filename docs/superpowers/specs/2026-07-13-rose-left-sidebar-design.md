# Rose 左侧二级菜单与页面布局重构设计

## 目标

将 Rose Diff Studio 从顶部平铺导航调整为固定左侧导航，按业务工作流程组织所有已有入口。保留现有路由、控制器、表单、查询、导出和异步任务行为，仅重构布局、导航层级及视觉一致性。

## 信息架构

左侧导航分为以下一级菜单及二级菜单：

| 一级菜单 | 二级菜单 | 路由 |
| --- | --- | --- |
| 概览 | 无 | `/` |
| 数据准备 | 交易导入 | `/config/import` |
| 数据准备 | 交易配置 | `/config/trans` |
| 数据准备 | 字段映射 | `/config/fields` |
| 数据准备 | 录制配置 | `/config/recording` |
| 执行分析 | 采样指令 | `/sampling/commands` |
| 执行分析 | 统计历史 | `/sampling/summaries` |
| 执行分析 | 交易级差异 | `/samples/transaction-diffs` |
| 执行分析 | 字段级差异 | `/samples/field-diffs` |
| 运维工具 | 报文查询 | `/messages/flow-logs` |
| 运维工具 | 报文录入 | `/messages/flow-logs/new` |
| 运维工具 | 数据迁移 | `/migration/commands` |
| 运维工具 | SQL 迁移 | `/migration/sql-commands` |

“概览”是独立入口。当前页面所属一级菜单默认展开，其他一级菜单默认收起；用户点击另一一级菜单时，前一组立即收起。二级菜单点击后直接导航。首页不展开任何功能分组。

## 页面框架

所有页面统一采用以下框架：

1. 顶部细工具栏显示产品名称、当前工作域及用户占位信息。
2. 左侧固定导航栏承载品牌、概览入口和一级/二级菜单。
3. 主内容区使用面包屑、页面标题、辅助说明和主操作构成标题区。
4. 查询、表单、统计、表格和图表按业务需要放入无嵌套的内容区块；已有页面功能及字段不变。

视觉采用深青色侧栏、白灰内容底色、橙色主要操作和状态强调色。当前一级或二级菜单通过背景与左侧强调线清楚标识。侧栏宽度固定，内容区在大屏中占用剩余空间；在窄屏中导航转为可收起的抽屉，避免压缩表格和表单可用宽度。

## 模板与样式边界

`fragments/layout.html` 负责导航树和全局框架。各业务页面继续通过现有 `active` 模型属性标识当前入口，不改控制器契约。`app.css` 提供框架、侧栏、导航状态、通用标题区和响应式规则；各页面专属样式保留在既有选择器下并适配新容器。

导航展开状态由客户端脚本根据当前 `active` 值和用户点击维护；不需要新增后端状态或数据库字段。无 JavaScript 时，当前组保持可见，链接仍正常可用。

## 错误处理与兼容性

未知或未分组的 `active` 值不应阻断页面渲染：侧栏仅显示无选中项，内容区照常展示。长二级菜单在侧栏内部滚动，保证品牌及概览入口稳定可见。所有已有链接、表单提交、导出链接和后台进度轮询 URL 均保持不变。

## 验收与测试

1. 模板测试验证全部一级/二级菜单、路由和 `active` 高亮存在，旧顶部平铺菜单不存在。
2. CSS 测试验证桌面侧栏、当前组展开、移动端抽屉/收起规则以及内容区布局选择器存在。
3. 运行现有 Maven 测试，确认各模板渲染、导出和控制器行为不回归。
4. 本地启动应用后，在首页、数据准备、执行分析和运维工具各抽查一页，验证当前组自动展开、切换组时自动收起、二级链接有效、窄屏布局不遮挡内容。
