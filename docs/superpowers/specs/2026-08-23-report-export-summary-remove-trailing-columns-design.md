# 报表导出汇总页尾部列删除设计

## 背景

日报、未脱敏日报和周报的“汇总信息”Sheet 当前在“问题总数”之后继续输出以下人工维护列：

- 上一批次区域：已解决问题分类统计（待验证）、问题解决进度。
- 本批次区域：上一批次未解决问题数量、上轮问题解决率、上一批次已解决问题分类统计（待验证）、问题解决进度。

这些列不再需要。所有汇总区块应统一以“问题总数”作为最后一列。

## 目标行为

- 日报、未脱敏日报和周报的“汇总信息”Sheet 只生成第 1 至第 13 列（Excel A 至 M）。
- 上一批次和本批次区块均以“问题总数”结束。
- 不生成 N 列及之后的表头、数据单元格、合计单元格、列宽或合并区域。
- 区块标题和公式说明行的合并范围统一截止 M 列。
- 公式说明只保留“成功率”和“比对通过率”，删除“上轮问题解决率”说明。

## 实现范围

修改 `ReportExportExcelService` 的汇总 Sheet 渲染逻辑：

- 将上下区块的最后一列统一为第 13 列（零基索引 12）。
- 汇总表头只渲染批次、领域、接口覆盖、交易量、交易状态分类、成功率、比对通过率和问题总数。
- 数据行和合计行写到问题总数后停止。
- 汇总页只设置 A 至 M 的列宽。
- 删除仅供已移除列使用的表头和空白单元格写入逻辑；不改变汇总数据查询和统计模型。

## 不在范围内

- 不改变领域明细、接口比对汇总、问题处理延迟分布和全量问题清单 Sheet。
- 不改变数据库表结构、批次选择、重复问题统计或其他数据计算口径。
- 不改变导出端点、文件名和下载入口。
- 不修改既有 Excel 文件；变更只影响后续生成的文件。

## 测试设计

在 `ReportExportExcelServiceTest` 中先增加或调整失败断言，再修改生产代码：

- 验证上一批次和本批次主表头均以“问题总数”结束。
- 验证两个区块的标题、主表头和公式说明合并区域均截止零基索引 12。
- 验证数据行与合计行的最后一个单元格均为 M 列，N 列为空且未创建。
- 验证公式说明包含“成功率”和“比对通过率”，且不包含“上轮问题解决率”。
- 分别覆盖日报和周报工作簿；未脱敏日报复用同一汇总生成路径，由现有入口回归测试保障。

完成定向测试后运行完整 Maven 测试套件，确认其他导出 Sheet 和 Web 下载行为没有回归。
